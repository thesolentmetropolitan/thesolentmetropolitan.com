## What was tricky — the audit deadlock

Drupal 11.3.7–11.3.9 require `twig/twig ~v3.22.0`. All three 3.22.x releases (3.22.0/1/2) have an open security advisory ([CVE-2026-46634](https://symfony.com/cve-2026-46634): `template_from_string()` escapes a SourcePolicy-driven sandbox). Composer 2.9.5's `audit.block-insecure` gate refuses to install advisory-flagged packages, so the update wouldn't resolve at all.

The 11.2.x track is in the same bind — 11.2.11 (latest 11.2) requires `symfony/mailer 7.3.5+` which has its own advisory. There is currently **no completely-clean version of Drupal 11.x** because the surrounding ecosystem has unfixed transitive advisories.

Resolved by adding an `audit.ignore` map to `composer.json` listing the ten twig 3.22.x advisory IDs with a documented reason. The previous Drupal 11.2.2 install was ALREADY listed against multiple SA-CORE advisories (audit only blocks new installs, not existing ones), so the net effect is: we trade several already-public Drupal-core CVEs (now fixed in 11.3.9) for one twig sandbox-escape vuln (still open in 3.22.x).

For this site — no `template_from_string()` usage in custom code, no untrusted Twig templates accepted from users — the twig vuln has very limited realistic exposure. Mitigated by site architecture; remove the `audit.ignore` entries when Drupal core bumps the twig constraint to `~v3.23.0` (likely 11.3.10 or 11.4.x).

## Remaining advisory

`psy/psysh <= 0.11.22 || >=0.12.0 <=0.12.18` — **medium** severity local privilege escalation via `.psysh.php` auto-load in CWD ([CVE-2026-25129](https://github.com/advisories/GHSA-4486-gxhx-5mg7)). PsySH is a CLI debugger that ships as a dev dependency of drush (used by `drush php` for an interactive shell). Not exposed via HTTP. Risk surface: someone with shell access to the server who can drop a `.psysh.php` into a directory the operator later `cd`s into and runs `drush php` from. Standard server hygiene mitigates. Will be picked up by a future drush release.

## Deploying to live

```bash
git pull
composer install --no-dev    # bring vendor/ up to the new lock
drush updb -y                 # apply the 13 post-update tasks
drush cr
```

(`--no-dev` skips drush's dev-only `psy/psysh` dep on production — harmless to omit if your live deploy already does `composer install` without it.)

**Verify on live after deploy:**

- `drush status` — should report `Drupal version: 11.3.9`.
- Visit `/sectors` and `/culture` — kickers still render, no PHP errors.
- Visit `/explore/events` — events listing still dedup'd (custom hook from yesterday).
- Edit an event and resave — Smart Date should still store correctly (yesterday's `default_tz=custom` fix is independent of this update).

Older events (114–117) do have proper `/event/...` aliases. This is a pre-existing gap from before today's update — **flagged for follow-up**, not in scope here.
