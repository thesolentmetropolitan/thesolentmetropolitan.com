## Production deploy sequence

Correct order for a code+config update deploy — **updb before cim**:

```
# from project root on prod
drush state:set system.maintenance_mode 1 -y
drush cr                       # prime caches for new code
git pull
composer install
drush updb -y                  # DB/update hooks first
drush cim -y                   # then config import
drush cr
drush state:set system.maintenance_mode 0 -y
```

Take a DB backup first: `drush sql:dump --gzip --result-file=...`.

Note: `scripts/deploy.sh` has no `updb` step (it was written for
config/content-only deploys). For this deploy either run the sequence above
manually or add a `drush updb -y` step to deploy.sh before config:import.
Prod drush is `./drush-dir/drush` (see docs/devops).

## Why updb before cim

Update hooks adapt the existing DB/config to the new code's expectations
(e.g. the search module split). Importing config first would try to enable
`search_node` before the update hook that creates its expected state has
run. Drush's own `drush deploy` command codifies this order:
updb → cim → cr.
