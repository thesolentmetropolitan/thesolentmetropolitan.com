## The advisory

SA-CORE-2026-014 (14 Oct 2026), critical 19/25: remote code execution via the
Field UI module. Not directly exploitable with core alone, but at least one
exploit path through contributed modules needs no authentication. Affected:
11.4.0–11.4.9. Fixed: 11.4.10. PSA-2026-10-12 warned exploits may follow
within hours or days, so this wants deploying promptly.

## What `composer audit` added to the scope

After the core update Composer reported four advisories already present in
the lock file. Both are security fixes, so they are in this release:

| Package | From | To | Why |
|---|---|---|---|
| drupal/core (+ scaffold, project-message, recommended) | 11.4.8 | 11.4.10 | SA-CORE-2026-014 |
| drupal/menu_link_attributes | 1.7.0 | 1.10.0 | SA-CONTRIB-2026-209, XSS 11/25 (fixed in 1.8.0) |
| drupal/svg_image | 3.2.4 | 3.2.5 | raises its constraint to svg-sanitize ^1.0 |
| enshrined/svg-sanitize | 0.22.0 | 1.0.0 | CVE-2026-107379/80/81: stored XSS via DTD entities, DoS via `<use>` nesting and DTD attribute declarations |
| symfony/* | 7.4.x | 7.4.21 | transitive |

svg-sanitize 1.0.0 could not move on its own because svg_image 3.2.4 pins
`>=0.22 <1.0`; 3.2.5 is the release that lifts that.

Not updated: klaro 3.1.2 and single_content_sync 1.4.18 (no advisories, left
for a routine update); custom_field 5.x (major, separate job as before).

## menu_link_attributes database updates

1.10.0 brings `update_8004` plus two post-updates. 8004 strips attribute
definitions it considers unsafe from `menu_link_attributes.config` and renames
underscore attribute names to hyphens; the post-updates repair over-eager
removals from an earlier 8004. Our config defines only `container_class`,
`class` and `target`, all safe. Rehearsed: config unchanged (`config:status`
clean), and the two menu links carrying attributes (ids 89 and 101) have
identical serialised `link__options` before and after.

## Production

```
git pull origin main
bash scripts/release-2026-10-14-core-security.sh
```

The script backs up the DB, enters maintenance mode, runs `composer install
--no-dev` from the lock file, `updatedb`, cache rebuild, checks config is in
sync, runs `composer audit`, and leaves maintenance mode. If `config:status`
reports a difference in `menu_link_attributes.config`, production had an
attribute definition that local does not; review before importing.

Note the previous release (2026-10-03, core 11.4.8) is merged to main but it
is not recorded here whether it has been run on production. This script
supersedes it: `composer install` from the new lock covers both, and
`updatedb` will run whatever is pending.
